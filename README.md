# 架构设计案例实战学习指南

> 通过真实业务场景的架构设计挑战，锤炼系统设计思维与决策能力。
> 每个案例聚焦一个核心架构难题，要求在约束条件下做出权衡取舍。

## 使用方法

1. **独立思考**：先阅读场景描述，尝试自行设计（限时 30-45 分钟）
2. **对照参考**：再阅读设计解析，对比自己的方案，找出差异
3. **深度追问**：对每个案例的延伸问题进行探索，拓展思维边界
4. **反复练习**：隔一段时间重新审视同一案例，检验认知是否深化

## 难度说明

- **★★★ 进阶**：核心架构问题清晰，侧重单一技术领域的深度设计
- **★★★★ 高级**：涉及多个架构领域的交叉，需要系统性权衡
- **★★★★★ 专家**：存在根本性技术矛盾，没有标准答案，考验架构哲学

## 架构设计核心原则速查

### 设计前的灵魂三问
1. **系统的核心约束是什么？** （不是"要做什么"，而是"不能怎样"）
2. **哪里是变化的、哪里是稳定的？** （把变化隔离，让稳定固化）
3. **失败时怎样优雅降级？** （不是"如何不失败"，而是"失败了怎么办"）

### 权衡取舍的常见维度

| 维度对 | 典型取舍场景 |
|--------|------------|
| 一致性 vs 可用性 | 分布式系统的基础权衡（CAP） |
| 延迟 vs 吞吐 | 批量处理 vs 逐条响应 |
| 简单 vs 灵活 | 通用方案 vs 定制优化 |
| 成本 vs 可靠性 | 单机 vs 集群 / 同步 vs 异步 |
| 实时 vs 最终 | 同步调用 vs 异步事件 |
| 安全 vs 便捷 | 零信任 vs 信任内网 |

### 架构评审检查清单
- [ ] 是否识别了核心瓶颈并针对性设计？
- [ ] 是否考虑了故障场景和降级策略？
- [ ] 数据一致性模型是否明确且可验证？
- [ ] 水平扩展是否存在单点或瓶颈？
- [ ] 关键路径是否有可观测性？
- [ ] 方案复杂度是否与问题规模匹配？
- [ ] 是否有明确的容量规划和扩缩容策略？
